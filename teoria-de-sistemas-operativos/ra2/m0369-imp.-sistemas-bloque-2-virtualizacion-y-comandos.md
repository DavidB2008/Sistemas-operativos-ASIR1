## 1. Virtualización

La **virtualización** permite ejecutar un sistema informático simulado por software dentro de un equipo físico. Así podemos instalar un sistema operativo invitado sin tener que dedicarle un ordenador independiente.

### 1.1. Conceptos fundamentales

* **Equipo anfitrión (host):** ordenador físico en el que se ejecuta el software de virtualización.
* **Máquina virtual (VM o MV):** entorno virtual que simula un ordenador, con procesador, memoria, almacenamiento y dispositivos virtuales.
* **Sistema operativo anfitrión:** sistema operativo instalado en el equipo físico.
* **Sistema operativo invitado (guest):** sistema operativo instalado dentro de la máquina virtual.
* **Imagen ISO:** archivo que contiene una imagen de instalación de un sistema operativo.
* **Disco virtual:** archivo que actúa como disco duro de la máquina virtual.
* **Hipervisor:** software o capa que crea y administra las máquinas virtuales. VirtualBox es un hipervisor alojado que se instala como aplicación sobre el sistema operativo anfitrión.

### 1.2. Ventajas de la virtualización

1. **Aislamiento:** los cambios realizados dentro de una VM normalmente quedan dentro de esa máquina y no afectan directamente al sistema anfitrión.
2. **Prácticas seguras:** permite probar instalaciones, comandos, configuraciones y servicios sin usar un equipo dedicado.
3. **Varios sistemas operativos:** se pueden tener, por ejemplo, máquinas con Windows, Debian y Ubuntu en el mismo ordenador.
4. **Recuperación:** las instantáneas permiten volver a un estado anterior de una máquina cuando se cumplen las condiciones necesarias.
5. **Clonación y duplicación:** se puede crear una copia de una VM o de su disco para repetir prácticas.
6. **Ahorro de hardware:** varios entornos de laboratorio pueden ejecutarse sobre un único equipo físico.
7. **Reproducibilidad:** las máquinas se pueden configurar de forma parecida para repetir pruebas o compartir un laboratorio.

La virtualización también tiene límites: las máquinas comparten los recursos físicos, por lo que varias VM activas pueden consumir mucha RAM, CPU y almacenamiento. Una máquina virtual no sustituye por sí sola a una copia de seguridad independiente.

### 1.3. Tipos de virtualización

En un laboratorio de sistemas conviene distinguir:

* **Virtualización de sistemas o de hardware:** simula un ordenador completo para instalar un sistema operativo invitado. Es el uso habitual de VirtualBox.
* **Virtualización de aplicaciones mediante contenedores:** aísla aplicaciones y dependencias sin simular necesariamente un ordenador completo; Docker es un ejemplo de esta tecnología.
* **Virtualización alojada:** el hipervisor se ejecuta sobre un sistema operativo anfitrión, como VirtualBox instalado en Windows o Linux.
* **Virtualización sobre hardware (bare metal):** el hipervisor se instala directamente sobre el hardware o en una capa muy próxima a él.

### 1.4. Requisitos básicos

Antes de crear máquinas virtuales, comprueba:

* Que el procesador admita virtualización por hardware y que esté habilitada en BIOS/UEFI cuando sea necesario.
* Que haya suficiente memoria RAM para el anfitrión y para cada invitado.
* Que exista espacio libre para los discos virtuales y las ISO.
* Que la versión de VirtualBox sea compatible con el sistema anfitrión.
* Que la ISO proceda de una fuente fiable y, si se facilita, que su hash coincida con el valor oficial.
* Que se hayan definido los recursos de cada VM de acuerdo con el sistema que se instalará.

## 2. VirtualBox: instalación, configuración y máquinas virtuales

El material del bloque propone revisar la web del fabricante, las versiones disponibles, la descarga, la instalación, la configuración, los modos de red y las funciones de exportación e importación.

### 2.1. Flujo de trabajo recomendado

1. **Consultar la web oficial:** revisar las versiones disponibles y seleccionar la apropiada para el sistema anfitrión.
2. **Descargar el instalador:** usar la web oficial de VirtualBox y descargar también la ISO del sistema operativo invitado desde su fuente oficial.
3. **Instalar VirtualBox:** seguir el asistente. Durante la instalación pueden añadirse controladores de red virtuales; la conectividad puede interrumpirse brevemente.
4. **Crear una VM:** indicar nombre, tipo y versión del sistema operativo, memoria RAM, número de procesadores virtuales cuando proceda y disco virtual.
5. **Montar la ISO:** seleccionar la imagen de instalación como unidad óptica virtual y arrancar la máquina.
6. **Instalar el sistema operativo:** seguir el asistente de instalación dentro de la VM.
7. **Configurar la red:** elegir NAT, red NAT, red interna, solo anfitrión, adaptador puente u otro modo según el objetivo de la práctica.
8. **Instalar herramientas de integración:** en Linux, las Guest Additions pueden mejorar la integración del ratón, la resolución y otras funciones.
9. **Crear una instantánea:** guardar un punto de retorno antes de realizar cambios importantes.
10. **Exportar o clonar cuando sea necesario:** utilizar las funciones de VirtualBox para transportar o duplicar el entorno.

### 2.2. Exportación e importación

La **exportación** permite empaquetar una máquina virtual para trasladarla o compartirla; el formato habitual de intercambio de VirtualBox es OVF/OVA. La **importación** permite incorporar ese paquete en otro entorno de VirtualBox. Tras importar, hay que revisar recursos, adaptadores de red, rutas de disco y cualquier ajuste dependiente del equipo.

No debe confundirse exportar una VM con copiar sin más uno de sus archivos de disco: una máquina puede depender de varios archivos y de su configuración.

## 3. Comprobación de integridad mediante hashes

Al descargar distribuciones Linux, imágenes ISO y ejecutables conviene verificar su **hash**. Un hash es una huella calculada a partir del contenido de un archivo. Si se calcula con el mismo algoritmo sobre el mismo archivo, el resultado debería coincidir con el valor publicado por la fuente de confianza.

### 3.1. Algoritmos mencionados en el material

| Algoritmo | Tamaño de salida indicado |
| --------- | ------------------------: |
| MD5       |                  128 bits |
| SHA-1     |                  160 bits |
| SHA-256   |                  256 bits |
| SHA-512   |                  512 bits |

Para comprobar descargas actuales, es preferible usar SHA-256 o SHA-512 cuando la fuente los publique. MD5 y SHA-1 ya no se consideran adecuados para usos de seguridad frente a ataques de colisión.

### 3.2. Comprobar una ISO con PowerShell

El material propone descargar Ubuntu junto con el hash SHA-256 esperado. En PowerShell, desde la carpeta donde se encuentran los archivos:

```powershell
$hashActual = Get-FileHash -Path ".\distro.iso" -Algorithm SHA256
$hashGuardado = Get-Content -Path ".\hash-guardado.txt"

if ($hashActual.Hash -eq $hashGuardado.Trim()) {
    Write-Output "El archivo no ha cambiado, los hashes coinciden."
} else {
    Write-Output "El archivo ha cambiado, los hashes no coinciden."
}
```

**Qué hace cada parte:**

1. `Get-FileHash` calcula el hash del archivo ISO con el algoritmo indicado.
2. `Get-Content` lee el hash esperado guardado en el archivo de texto.
3. La condición compara el hash calculado con el esperado.
4. Si coinciden, el archivo coincide con la huella publicada; si no, hay que revisar la descarga y el valor de referencia.

El archivo `hash-guardado.txt` debe contener el valor SHA-256 esperado, obtenido de la web oficial. No se debe comparar un hash calculado únicamente consigo mismo ni utilizar un valor de una fuente desconocida.

## 4. Modos de red de VirtualBox

El modo de red determina cómo se comunica una máquina virtual con otras VM, con el anfitrión, con la red física o con Internet. La elección depende del objetivo del laboratorio.

### 4.1. NAT

* La VM recibe una dirección privada de una red gestionada por VirtualBox.
* La máquina virtual puede iniciar conexiones hacia el exterior, por ejemplo para acceder a Internet.
* Por defecto, un equipo externo no puede iniciar directamente una conexión hacia un servicio de la VM sin configurar redirección de puertos.
* Es una opción sencilla para que una VM tenga salida a Internet sin convertirse en un equipo directamente accesible desde la red local.

**Ejemplo de uso:** instalar actualizaciones en una VM Linux sin exponer directamente sus servicios a otros equipos de la LAN.

### 4.2. Red NAT

* Permite que varias máquinas virtuales compartan una red NAT.
* Se puede configurar una red y su servicio DHCP.
* Las VM de esa red pueden comunicarse entre sí y salir hacia redes externas, según la configuración.
* Puede ser útil para laboratorios con varias máquinas virtuales que necesitan conectividad externa.

El material señala que el uso de ICMP puede ser limitado y que, en el escenario descrito, puede funcionar `ping` mientras que `traceroute` no muestra todos los saltos. El comportamiento concreto depende de la configuración y de la versión.

### 4.3. Red interna

* Crea una red privada entre máquinas virtuales que tengan configurado el mismo nombre de red interna.
* No conecta por sí sola esas VM con el anfitrión, la red física ni Internet.
* Es apropiada para prácticas aisladas, como configurar un cliente y un servidor sin exponerlos a la red externa.

**Ejemplo:** una VM con un servidor web y otra con un cliente, ambas conectadas a una red interna para probar el servicio.

### 4.4. Solo anfitrión (Host-only)

* Crea conectividad entre el equipo anfitrión y las VM que utilizan esa red.
* No proporciona por sí sola acceso a la red física ni a Internet.
* Es útil cuando se necesita administrar o probar una VM desde el anfitrión, pero se desea aislarla de la LAN.

### 4.5. Adaptador puente

* Conecta la VM a la red física a través del adaptador de red del anfitrión.
* La VM aparece en la red como otro equipo y normalmente obtiene una IP del DHCP de esa red, si existe.
* Puede permitir que otros equipos de la LAN accedan a los servicios de la VM.
* Debe usarse con cuidado en redes públicas o no confiables, porque la VM queda más directamente expuesta a la red.

### 4.6. Controlador genérico

El material menciona un modo de controlador genérico que requiere un controlador específico. Puede permitir el uso de túneles UDP para conectar máquinas alojadas en distintos anfitriones o redes VDE para conexiones con un conmutador Ethernet virtual. Es una opción especializada, no la primera elección para prácticas básicas.

### 4.7. Comparativa rápida

| Modo                 | Salida a Internet           | Comunicación con el anfitrión                                             | Comunicación entre VM                       | Uso típico                                 |
| -------------------- | --------------------------- | ------------------------------------------------------------------------- | ------------------------------------------- | ------------------------------------------ |
| NAT                  | Normalmente sí              | La VM puede iniciar conexiones; el acceso entrante requiere configuración | Depende del escenario y de la configuración | Una VM con salida sencilla a Internet      |
| Red NAT              | Normalmente sí              | Según la configuración                                                    | Sí, dentro de la misma red NAT              | Laboratorio con varias VM y salida externa |
| Red interna          | No, por sí sola             | No directamente                                                           | Sí, en la misma red interna                 | Laboratorio aislado cliente-servidor       |
| Solo anfitrión       | No, por sí solo             | Sí                                                                        | Sí, si comparten la red host-only           | Administrar VM desde el anfitrión          |
| Adaptador puente     | Según la red física         | Sí, a través de la LAN                                                    | Como equipos de la LAN                      | VM accesible en la red local               |
| Controlador genérico | Depende de la configuración | Depende de la configuración                                               | Depende del controlador y túnel             | Escenarios de red especializados           |

## 5. Instalación de Debian o Ubuntu y Guest Additions

El material propone instalar Debian o Ubuntu en VirtualBox y después instalar las **Guest Additions** para mejorar la integración entre la VM y el anfitrión.

### 5.1. Preparar la instalación

1. Descarga la ISO de Debian o Ubuntu desde su web oficial.
2. Crea una nueva máquina virtual en VirtualBox.
3. Asigna recursos adecuados de RAM, CPU y almacenamiento.
4. Monta la ISO como unidad óptica virtual.
5. Inicia la VM y sigue el instalador de la distribución.
6. Al terminar, reinicia y comprueba que el sistema invitado arranca correctamente.

### 5.2. Instalar dependencias y Guest Additions

Según el material, en Debian/Ubuntu se instalan primero las herramientas de compilación indicadas y después se ejecuta el instalador de Guest Additions. El procedimiento puede variar según la versión de VirtualBox y de Linux.

```bash
sudo apt-get update
sudo apt-get install gcc make perl
```

Después de montar la imagen de Guest Additions desde el menú **Dispositivos** de VirtualBox, hay que entrar en el directorio del medio montado y ejecutar el instalador, por ejemplo:

```bash
sudo ./VBoxLinuxAdditions.run
```

El comando `./VBoxLinuxAdditions.run` solo funciona si la terminal está situada en el directorio que contiene ese archivo y el medio está montado. En algunos sistemas también pueden ser necesarios los encabezados del kernel correspondientes. Si el instalador informa de errores, hay que leerlos y resolver las dependencias que falten en lugar de repetir el comando sin comprobar el resultado.

### 5.3. Comprobar el resultado

Después de instalar y reiniciar cuando sea necesario, prueba:

* Cambiar el tamaño de la ventana y comprobar si se ajusta la resolución.
* Mover el ratón entre anfitrión e invitado de forma más fluida.
* Probar copiar y pegar entre ambos, si se ha habilitado la función correspondiente en la configuración de VirtualBox.
* Comprobar que la VM sigue arrancando correctamente.

## 6. Discos virtuales, clonación e instantáneas

### 6.1. Disco virtual VDI

VirtualBox puede guardar el disco duro de una VM en un archivo de imagen, por ejemplo con extensión `.vdi`. Ese archivo contiene el almacenamiento que el sistema invitado ve como un disco duro.

**Importante:** copiar directamente el archivo VDI desde el explorador no siempre es la forma adecuada de crear una segunda VM. Pueden existir identificadores, dependencias o referencias de configuración que deben gestionarse correctamente.

### 6.2. Clonar un disco con VBoxManage

El material presenta el comando:

```
VBoxManage clonehd imagen_original.vdi imagen_backup.vdi
```

En versiones recientes de VirtualBox, el subcomando recomendado puede ser `clonemedium`; si `clonehd` no está disponible, se puede usar:

```
VBoxManage clonemedium disk imagen_original.vdi imagen_backup.vdi
```

Ejecuta el comando desde el directorio donde están los archivos o especifica las rutas completas. Si `VBoxManage` no está en la variable `PATH`, hay que indicar la ruta completa al ejecutable. El material propone localizar el ejecutable y arrastrarlo a la terminal para insertar su ruta.

Una vez creado el disco clonado, se puede utilizar para crear o configurar otra VM. Hay que asegurarse de que cada máquina usa el disco correcto y de que no se intenta iniciar dos VM independientes con una misma imagen de disco escribible de manera insegura.

### 6.3. Instantáneas

Una **instantánea** registra un estado de una VM en un momento concreto para poder volver a él. Resulta útil antes de instalar software, cambiar la configuración de red o realizar pruebas arriesgadas.

Buenas prácticas:

* Crear una instantánea cuando el sistema está en un estado conocido y estable.
* Poner nombres descriptivos, como «Instalación limpia» o «Antes de configurar la red».
* No confundir instantáneas con copias de seguridad independientes: pueden depender de los archivos de la VM y ocupar espacio adicional.
* Eliminar las instantáneas que ya no se necesiten con cuidado y comprobar el almacenamiento disponible.

## 7. La shell de Windows y el PATH

Una **shell** es un intérprete que permite interactuar con el sistema mediante órdenes. En Windows se puede usar el Símbolo del sistema (CMD) o PowerShell; en este apartado se trabajan principalmente los comandos clásicos de CMD.

### 7.1. Abrir CMD

Se puede abrir de varias formas:

* Buscar `cmd` en el menú Inicio o en la lupa de la barra de tareas.
* Pulsar `Windows + R`, escribir `cmd` y pulsar Intro.

El prompt muestra el contexto en el que se ejecutarán las órdenes. Por ejemplo:

```
C:\Users\Alex>
```

La ruta anterior indica que la terminal está situada en la carpeta `C:\Users\Alex`.

### 7.2. Unidades lógicas

En Windows, las rutas suelen comenzar por una letra de unidad, como `C:\` o `D:\`. Para cambiar de unidad en CMD, se escribe la letra seguida de dos puntos:

```bat
D:
```

El prompt cambiará a la unidad D si el cambio se realiza correctamente. En cambio, `cd` se usa para cambiar de directorio dentro del contexto de la unidad actual, con algunas opciones para cambiar también de unidad.

### 7.3. Variable PATH

La variable de entorno `PATH` contiene una lista de directorios en los que Windows busca ejecutables cuando se escribe un comando sin especificar su ruta completa.

Para mostrarla en CMD:

```bat
echo %PATH%
```

Si un programa no se encuentra en una carpeta incluida en `PATH`, se puede ejecutar de otras formas:

* Indicando su **ruta absoluta**.
* Indicando una **ruta relativa** desde el directorio actual.
* Situándose primero en la carpeta donde está el ejecutable y escribiendo su nombre.

No conviene añadir carpetas desconocidas a `PATH`: puede provocar conflictos entre versiones o facilitar que se ejecute un archivo no deseado.

## 8. Rutas absolutas y relativas

Una ruta o **path** identifica dónde se encuentra un archivo o directorio.

### 8.1. Ruta absoluta

Especifica la ubicación desde una raíz conocida, incluyendo la unidad en Windows. No depende del directorio actual.

Ejemplo:

```
C:\Windows\System32\drivers
```

Esta ruta señala el directorio `drivers` dentro de `System32`, bajo `Windows` en la unidad C.

### 8.2. Ruta relativa

Describe una ubicación tomando como referencia el directorio actual. Su significado cambia si cambia el punto de partida.

Ejemplo: si el prompt está en `C:\Windows>`, la ruta relativa:

```
System32\drivers
```

lleva a `C:\Windows\System32\drivers`.

### 8.3. Ejemplos de navegación en CMD

Partiendo de `C:\Users\Mindeos>`:

```bat
cd ..
```

Sube un nivel, hasta la carpeta superior.

Para ir a una ruta absoluta:

```bat
cd C:\Windows
```

Para acceder mediante una ruta relativa desde `C:\Windows>`:

```bat
cd System32\drivers
```

Para cambiar a la unidad D:

```bat
D:
```

Y para entrar en una carpeta llamada `ifp` en esa unidad:

```bat
cd ifp
```

Para listar el contenido de la carpeta actual:

```bat
dir
```

**Matiz importante:** en CMD, `cd D:\ifp` no es lo mismo que escribir solo `cd ifp` desde otra unidad. Para cambiar de unidad y directorio conjuntamente puede utilizarse `cd /d D:\ifp`.

### 8.4. ¿Por qué utilizar rutas relativas?

Las rutas relativas facilitan mover un proyecto entre ubicaciones siempre que se conserve la estructura de carpetas. Por ejemplo, un programa que busca un archivo dentro de una subcarpeta del proyecto puede seguir funcionando aunque la carpeta raíz se traslade a otra unidad.

Las rutas absolutas son preferibles cuando el proceso necesita acceder a una ubicación exacta del sistema, como un archivo de configuración situado en una ruta fija. La elección depende de si interesa portabilidad o precisión sobre una ubicación concreta.

## 9. Estructura de directorios y caracteres reservados

### 9.1. Ejemplos de rutas en Windows y Linux

| Sistema   | Ejemplo de ruta                       |
| --------- | ------------------------------------- |
| Windows   | `C:\Users\Alex\Documents\archivo.txt` |
| GNU/Linux | `/home/alex/documentos/archivo.txt`   |

En Windows es habitual usar la barra invertida `\` como separador de directorios y letras de unidad. En Linux se usa `/` y las rutas parten de una única raíz del sistema de archivos.

### 9.2. Caracteres que no se pueden usar o tienen un significado especial

En Windows, los nombres de archivo no admiten normalmente los caracteres:

```
\ / : * ? " < > |
```

Los dos puntos se utilizan para designar unidades, como `C:`, y otros caracteres tienen significados especiales para rutas o comandos.

En Linux, la barra `/` separa directorios y el carácter nulo `\0` no puede formar parte de un nombre de archivo. Otros caracteres que Windows reserva, como `*`, `?`, comillas o barras invertidas, pueden aparecer en nombres Linux, aunque algunos requieren comillas o escapes al escribir comandos en una shell.

### 9.3. ¿Es lo mismo C:\Windows que C:\WINDOWS?

En Windows, los nombres de archivo y directorio suelen tratarse sin distinguir mayúsculas y minúsculas; por eso, en el uso normal, `C:\Windows` y `C:\WINDOWS` hacen referencia al mismo directorio. En Linux, los nombres de archivo distinguen mayúsculas y minúsculas: `archivo.txt` y `Archivo.txt` pueden ser dos archivos diferentes.

Este comportamiento se denomina **case sensitivity**. No debe generalizarse a todos los programas y sistemas de archivos: algunos entornos o configuraciones admiten excepciones.

## 10. Comandos básicos de CMD

Los comandos de esta sección se introducen en el Símbolo del sistema. Para conocer las opciones de un comando se puede escribir su nombre seguido de `/?`, por ejemplo:

```bat
dir /?
```

### 10.1. Mostrar información y controlar la consola

| Comando     | Función                                                            | Ejemplo                          |
| ----------- | ------------------------------------------------------------------ | -------------------------------- |
| `rem`       | Añade un comentario a un archivo por lotes.                        | `rem Esta línea explica el paso` |
| `echo`      | Muestra texto o el estado de la visualización de órdenes.          | `echo Hola`                      |
| `@echo off` | En un script, evita que se muestre cada orden antes de ejecutarse. | `@echo off`                      |
| `type`      | Muestra el contenido de un archivo de texto en la consola.         | `type notas.txt`                 |
| `cls`       | Limpia la pantalla de la consola.                                  | `cls`                            |
| `set`       | Muestra o define variables de entorno de la sesión CMD.            | `set`                            |
| `exit`      | Cierra la sesión de CMD actual.                                    | `exit`                           |

### 10.2. Listar y navegar por directorios

| Comando        | Función                                                                 | Ejemplo              |
| -------------- | ----------------------------------------------------------------------- | -------------------- |
| `dir`          | Lista archivos y carpetas del directorio actual o de una ruta indicada. | `dir C:\Windows`     |
| `cd`           | Cambia el directorio actual.                                            | `cd Documents`       |
| `cd ..`        | Sube al directorio padre.                                               | `cd ..`              |
| `md` / `mkdir` | Crea un directorio.                                                     | `mkdir practicas`    |
| `rd` / `rmdir` | Elimina un directorio vacío.                                            | `rmdir practicas`    |
| `tree`         | Muestra la estructura de directorios en forma de árbol.                 | `tree C:\Users\Alex` |

Para eliminar un directorio y su contenido, el material muestra:

```bat
rd practicas /s
```

El modificador `/s` elimina también los subdirectorios y archivos. **Es una operación destructiva**: comprueba la ruta y el contenido antes de confirmar. Si se solicita confirmación, sigue las indicaciones de la consola.

### 10.3. Crear, copiar, mover, renombrar y borrar archivos

| Comando          | Función                                                                           | Ejemplo                                 |
| ---------------- | --------------------------------------------------------------------------------- | --------------------------------------- |
| `copy`           | Copia archivos.                                                                   | `copy archivo.txt C:\DirectorioDestino` |
| `move`           | Mueve archivos o directorios; el elemento deja de estar en la ubicación original. | `move archivo.txt C:\DirectorioDestino` |
| `ren` / `rename` | Cambia el nombre de un archivo o directorio.                                      | `ren antiguo.txt nuevo.txt`             |
| `del`            | Elimina archivos.                                                                 | `del archivo.txt`                       |
| `attrib`         | Muestra o modifica atributos de archivos y carpetas.                              | `attrib archivo.txt`                    |
| `type`           | Lee el contenido textual de un archivo.                                           | `type archivo.txt`                      |

Ejemplos adicionales del material:

```bat
copy origen destino
move origen destino
ren nombre_antiguo nombre_nuevo
del *.txt
```

El comando `del *.txt` elimina los archivos que coinciden con el patrón en el directorio actual. Antes de utilizarlo, es recomendable ejecutar `dir *.txt` para comprobar qué elementos coinciden.

### 10.4. Comprobar el disco y la red

| Comando    | Función                                                                                                                                      | Ejemplo                       |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| `chkdsk`   | Comprueba el sistema de archivos y el estado lógico de un volumen; algunas reparaciones requieren permisos elevados y desmontaje o reinicio. | `chkdsk C:`                   |
| `format`   | Prepara un volumen con un sistema de archivos, borrando los datos existentes de ese volumen.                                                 | Consultar primero `format /?` |
| `ipconfig` | Muestra la configuración IP de los adaptadores de red.                                                                                       | `ipconfig /all`               |
| `ping`     | Comprueba la respuesta de conectividad hacia un destino mediante ICMP cuando está permitido.                                                 | `ping google.com`             |

**Precaución:** no ejecutes `format` sobre un volumen que contenga datos que quieras conservar. Para diagnosticar la red, recuerda que un `ping` fallido no demuestra por sí solo que un equipo esté apagado: ICMP puede estar bloqueado por un firewall.

### 10.5. Obtener ayuda

Muchos comandos de Windows muestran su sintaxis y opciones con el modificador `/?`. Ejemplos:

```bat
copy /?
ipconfig /?
mkdir /?
```

La ayuda es especialmente importante antes de utilizar parámetros que borran datos o modifican la configuración del sistema.

## 11. Comodines

Los **comodines** son caracteres especiales que permiten seleccionar nombres que coinciden con un patrón. Son útiles para listar, copiar o borrar grupos de archivos sin escribir cada nombre por separado.

### 11.1. Comodines habituales

* `*`: representa una secuencia de caracteres, que puede tener longitud variable.
* `?`: representa un único carácter en las coincidencias de CMD.

Ejemplos:

```bat
dir
dir p*ta.txt
dir *.txt
```

* `dir` lista el contenido del directorio.
* `dir p*ta.txt` muestra los nombres que comienzan por `p` y terminan en `ta.txt`, con cualquier secuencia intermedia.
* `dir *.txt` muestra los archivos cuya extensión coincide con `.txt`.

El material ilustra nombres como `pata.txt`, `peta.txt`, `pita.txt`, `pota.txt`, `pilota.txt` y `gato.txt`. El patrón `p*ta.txt` coincide con varios nombres que empiezan por `p` y acaban en `ta.txt`; `*.txt` coincide con todos los archivos con esa extensión.

### 11.2. Comodines en Linux

El material introduce también patrones de shell de Linux:

| Patrón   | Significado                                                                                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `?`      | Un carácter.                                                                                                                                                 |
| `*`      | Cualquier secuencia de caracteres, incluso vacía.                                                                                                            |
| `[abc]`  | Uno de los caracteres indicados: a, b o c.                                                                                                                   |
| `[^123]` | En el contexto de expresiones de corchetes del material, ninguno de los caracteres indicados; en shells como Bash suele usarse `[!123]` para negar la clase. |
| `[a-h]`  | Un carácter comprendido entre a y h.                                                                                                                         |

Estos patrones se interpretan por la shell antes de ejecutar el comando. Conviene distinguir los comodines de shell de las expresiones regulares, ya que no tienen exactamente la misma sintaxis ni el mismo significado.

## 12. Scripts de Windows y archivos BAT

Un **script** es una secuencia de órdenes guardada en un archivo para que un intérprete las ejecute. En Windows, los scripts de CMD suelen guardarse con la extensión `.bat` o `.cmd`. El material utiliza la extensión `.bat` para los archivos de procesamiento por lotes (_batch_).

### 12.1. Para qué sirven los scripts

Un script permite automatizar tareas repetitivas, por ejemplo:

* Mostrar información del sistema.
* Listar archivos o carpetas.
* Ejecutar varios comandos en orden.
* Guardar resultados en archivos de texto.
* Preparar informes de diagnóstico.
* Ejecutar tareas de mantenimiento de forma controlada.

El archivo contiene texto plano y puede editarse con un editor de texto, como Notepad. Si una secuencia de órdenes funciona correctamente en CMD, muchas de esas órdenes pueden reunirse en un archivo por lotes para volver a ejecutarlas.

### 12.2. Ejemplo básico de archivo BAT

Crea un archivo llamado `informe.bat` con este contenido:

```bat
@echo off
rem Ejemplo sencillo de informe del sistema
echo Informe basico del equipo
echo =========================
echo Usuario: %USERNAME%
echo Equipo: %COMPUTERNAME%
echo.
echo Configuracion de red:
ipconfig
echo.
echo Contenido de la carpeta actual:
dir
pause
```

**Explicación:**

1. `@echo off` oculta la repetición de las órdenes mientras se ejecutan.
2. `rem` introduce un comentario para la persona que lee el script.
3. `echo` muestra texto en la consola.
4. `%USERNAME%` y `%COMPUTERNAME%` son variables de entorno de Windows.
5. `ipconfig` muestra información de red.
6. `dir` lista los elementos de la carpeta actual.
7. `pause` espera a que el usuario pulse una tecla, para que la ventana no se cierre inmediatamente si se ejecuta con doble clic.

Para ejecutarlo, abre CMD, entra en la carpeta donde guardaste el archivo y escribe:

```bat
informe.bat
```

Este ejemplo sirve para aprender; antes de automatizar tareas en un entorno real, revisa qué datos recopila y dónde se guardan.

## 13. Scripts frente a programas compilados

El material compara los lenguajes interpretados y los programas compilados.

### 13.1. Script o programa interpretado

* El código suele estar guardado como texto legible.
* Un intérprete procesa las instrucciones, habitualmente línea a línea o mediante una forma equivalente de ejecución.
* Se puede editar con un editor de texto.
* Los cambios se pueden probar rápidamente sin un paso de compilación independiente.
* Ejemplos de lenguajes y entornos de scripting mencionados: Python, Ruby, JavaScript, shell de Linux, shell de Windows y PHP.

### 13.2. Programa compilado

Un compilador transforma el código fuente en código objeto o ejecutable. El material muestra un ejemplo en C:

```c
#include <stdio.h>

int main() {
    printf("Hello!");
    return 0;
}
```

Una compilación con GCC puede realizarse, por ejemplo, mediante:

```bash
gcc hello.c -o hello.exe
```

En Windows, los programas compilados suelen tener extensión `.exe`. El ejecutable contiene instrucciones en una representación que no se lee como texto fuente normal con un editor de texto básico.

### 13.3. Comparación

| Aspecto      | Scripts                                                                      | Programas compilados                                                                                    |
| ------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Ejecución    | Necesitan un intérprete o entorno de ejecución adecuado.                     | Normalmente se ejecuta el resultado compilado en un entorno compatible.                                 |
| Edición      | El código fuente suele ser texto legible y fácil de modificar.               | Para modificar el programa suele editarse el código fuente y volver a compilar.                         |
| Desarrollo   | Ciclo de edición y prueba generalmente rápido.                               | Incluye un paso de compilación.                                                                         |
| Rendimiento  | Depende del lenguaje y del intérprete; la interpretación puede añadir coste. | Puede ejecutar directamente código máquina y ser más eficiente en ciertos casos.                        |
| Tamaño       | El archivo de texto puede ser pequeño, pero requiere un entorno compatible.  | El ejecutable puede ocupar más o menos que el código fuente; no existe una regla universal.             |
| Uso habitual | Automatización, administración y tareas rápidas.                             | Aplicaciones donde interesa distribuir un ejecutable o controlar aspectos de rendimiento y compilación. |

El material destaca como ventajas del compilado la posible eficiencia de ejecución y el hecho de no interpretar las instrucciones de la misma manera en cada ejecución. Para los scripts destaca un ciclo de desarrollo corto y una mayor productividad al automatizar tareas. Estas ventajas dependen del lenguaje, la implementación y el programa concreto.

## 14. Práctica de scripts en Windows

### 14.1. Situación planteada

El material presenta una situación en la que varios ordenadores de una compañía muestran un comportamiento que se quiere supervisar. Como administradores de sistemas, se propone recopilar informes del estado de los equipos mediante comandos de Windows y programar el script para que se ejecute antes de que el usuario empiece a trabajar o en ese mismo momento.

### 14.2. Objetivo de la práctica

Crear un archivo por lotes que reúna información útil del sistema y la guarde en un informe. La práctica permite aplicar los comandos de CMD, variables de entorno, redirección de salida y programación de tareas.

### 14.3. Ejemplo orientativo de informe

El siguiente ejemplo amplía la idea de la práctica usando comandos vistos en el bloque. Guarda el informe en una carpeta llamada `Informes` dentro del perfil del usuario:

```bat
@echo off
set "CARPETA=%USERPROFILE%\Informes"
if not exist "%CARPETA%" mkdir "%CARPETA%"
set "INFORME=%CARPETA%\informe_sistema.txt"

echo Informe de estado del equipo > "%INFORME%"
echo Equipo: %COMPUTERNAME% >> "%INFORME%"
echo Usuario: %USERNAME% >> "%INFORME%"
echo Fecha: %DATE% >> "%INFORME%"
echo Hora: %TIME% >> "%INFORME%"
echo. >> "%INFORME%"

echo ==== Configuracion IP ==== >> "%INFORME%"
ipconfig /all >> "%INFORME%"
echo. >> "%INFORME%"

echo ==== Directorio de trabajo ==== >> "%INFORME%"
dir "%USERPROFILE%" >> "%INFORME%"

echo Informe guardado en: "%INFORME%"
```

**Cómo funciona la redirección:**

* `>` crea o sobrescribe el archivo de salida.
* `>>` añade la salida al final del archivo existente.
* Las comillas alrededor de rutas permiten trabajar con nombres de carpeta que contienen espacios.
* La comprobación `if not exist` evita intentar crear de nuevo una carpeta que ya existe.

Este ejemplo es orientativo y no sustituye al enunciado completo de la práctica del profesorado. Los informes contienen información del equipo y de la red; deben almacenarse con permisos adecuados y compartirse únicamente con las personas autorizadas.

### 14.4. Ejecutar el script al iniciar sesión

Para automatizar la ejecución, puede utilizarse el Programador de tareas de Windows. El flujo general es:

1. Guardar y probar el archivo `.bat` manualmente.
2. Abrir el Programador de tareas con `taskschd.msc`.
3. Crear una tarea y seleccionar el desencadenador apropiado, por ejemplo al iniciar sesión.
4. Configurar la acción para iniciar `cmd.exe` con el archivo por lotes como argumento, o ejecutar el archivo directamente si la configuración lo permite.
5. Comprobar la cuenta de ejecución, los permisos, la ruta de salida y las condiciones de la tarea.
6. Ejecutar una prueba y verificar que el informe se genera donde corresponde.

El material incluye referencias al planificador de tareas de Windows y a la ejecución de programas al iniciar el sistema. La configuración exacta debe adaptarse a si la tarea se ejecutará al iniciar el equipo, al iniciar sesión o de forma programada.

## 15. Trabajo con Linux

El último apartado introduce la terminal de GNU/Linux, el usuario administrador `root` y varios comandos básicos.

### 15.1. Estructura del prompt

El material representa el prompt con la estructura:

```
user@hostname
```

En muchas shells Linux el prompt también incluye la ruta actual y termina en un símbolo que orienta sobre los privilegios:

* `$` suele indicar que la shell pertenece a un usuario normal.
* `#` suele indicar que se está trabajando como `root`.

Estos símbolos son convenciones habituales, no una garantía absoluta: el prompt puede personalizarse.

### 15.2. ¿Qué es root?

**Root** es la cuenta administrativa tradicional de GNU/Linux. Tiene privilegios muy amplios para administrar el sistema, modificar archivos protegidos, instalar software y gestionar usuarios y servicios.

Las cuentas normales tienen menos privilegios por seguridad. Para tareas administrativas se suele utilizar `sudo` cuando está configurado, en lugar de permanecer todo el tiempo trabajando como root. Un comando ejecutado con privilegios elevados puede modificar partes críticas del sistema, por lo que hay que comprobarlo antes de pulsar Intro.

### 15.3. Comandos básicos de Linux

| Comando  | Función                                                                                             | Ejemplo          |
| -------- | --------------------------------------------------------------------------------------------------- | ---------------- |
| `ls`     | Lista archivos y directorios.                                                                       | `ls -la`         |
| `cd`     | Cambia el directorio actual.                                                                        | `cd Documentos`  |
| `pwd`    | Muestra la ruta absoluta del directorio actual.                                                     | `pwd`            |
| `passwd` | Cambia la contraseña del usuario o, con permisos apropiados, gestiona la contraseña de otra cuenta. | `passwd`         |
| `file`   | Intenta identificar el tipo de archivo.                                                             | `file archivo`   |
| `cat`    | Muestra o concatena contenido de archivos.                                                          | `cat notas.txt`  |
| `exit`   | Cierra la shell actual.                                                                             | `exit`           |
| `logout` | Cierra una shell de inicio de sesión cuando corresponde.                                            | `logout`         |
| `man`    | Abre el manual de un comando.                                                                       | `man ls`         |
| `info`   | Abre la documentación Info cuando el paquete proporciona esa documentación.                         | `info coreutils` |

### 15.4. Ayuda y parámetros

El material indica que la ayuda explica los parámetros de un comando y que existen formas resumidas de consultar las opciones.

* `man comando` abre la página de manual.
* `info comando` consulta la documentación Info disponible.
* Muchos comandos aceptan opciones que se pueden combinar; la combinación válida depende de cada comando.

Ejemplos:

```bash
man ls
ls --help
pwd
file archivo.txt
cat archivo.txt
```

No todos los comandos admiten exactamente el mismo formato de ayuda. Si una opción no funciona, consulta la página de manual o la ayuda específica del comando.

### 15.5. Comodines en Linux

Los comodines permiten seleccionar varios nombres a partir de patrones. Entre los patrones presentados en el material:

* `?`: un carácter.
* `*`: una secuencia de caracteres.
* `[abc]`: uno de los caracteres indicados.
* `[a-h]`: un carácter dentro del rango a–h.
* La negación de una clase de caracteres depende de la sintaxis de la shell; en Bash es común usar `[!123]`.

Ejemplos:

```bash
ls *.txt
ls archivo?
ls [abc]*
```

En una shell, los patrones normalmente se expanden antes de que el programa reciba los argumentos. El resultado depende de los nombres que existan en el directorio actual y de la sintaxis de la shell.
